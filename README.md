## 🎯 What it does

NetSage AI reads a network symptom, a topology note, and Cisco `show`-command
output, and returns a structured diagnosis: the likely **root cause**, the
**OSI layer**, a **confidence level**, the **evidence** it used, the
**next command** to run, and concrete **fix steps**. Every AI diagnosis is
cross-checked by an independent, deterministic Python rule checker, and must
be reviewed by a human (Accepted / Edited / Rejected) before it counts as
final — nothing is auto-applied to a real device.

## 🚀 Setup & Run Locally

### 1. Clone and install

```bash
git clone https://github.com/<your-username>/netsage-ai.git
cd netsage-ai
python3 -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### 2. Get a free Groq API key

Go to [console.groq.com](https://console.groq.com) → sign in (Google/GitHub
works) → **API Keys** → **Create API Key**. No credit card, works
immediately. Groq's free tier is fast (sub-second responses) and covers
14,400 requests/day on Llama 3.3 70B — plenty for this project.

You can provide it either way:
- **Recommended: Streamlit secrets** — put it in `.streamlit/secrets.toml`
  (copy from `.streamlit/secrets.toml.example`) for local dev, or in
  **App Settings → Secrets** when deployed on Streamlit Cloud. The app never
  asks for a key in the UI — it's resolved entirely server-side.
- **Environment variable** — copy `.env.example` to `.env` and fill it in, then:
  ```bash
  export GROQ_API_KEY=your_key_here   # macOS/Linux
  set GROQ_API_KEY=your_key_here      # Windows cmd
  ```

### 3. (Re)generate the case dataset (already included, but if you edit it)

```bash
python scripts/generate_cases.py
```

### 4. Test the rule checker standalone (optional)

```bash
python scripts/rule_checker.py
```

### 5. Run the app

```bash
streamlit run app.py
```

Open the URL Streamlit prints (usually `http://localhost:8501`).

## 🧭 Using the App

1. **Diagnose Cases** — pick a case, click "Run AI Diagnosis + Rule Checker".
   You'll see the AI's structured JSON diagnosis side-by-side with the
   independent rule checker's flags and the ground-truth expected fault.
2. **Review** — as the human reviewer, mark each case Accepted / Edited /
   Rejected. Edited/Rejected requires a note explaining what was wrong.
   This is what makes it "Responsible AI" — nothing is accepted blindly.
3. **Dashboard** — auto-updating charts: cases by category, review outcome
   split, severity distribution, AI-vs-expected match rate, and a full
   results table you can download as CSV.
4. **Responsible AI Log** — lists every Edited/Rejected case with the
   reviewer's explanation, and lets you export it straight to
   `responsible_ai_log.md` for submission.

## ⚠️ Responsible AI Notice

This tool is **advisory only**. It is designed to assist, not replace, a
network engineer's judgment. Every diagnosis requires human review before
any configuration change is made on a real or lab device — this is
enforced in the workflow, not just documented.
